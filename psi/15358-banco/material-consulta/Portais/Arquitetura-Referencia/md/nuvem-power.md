# Power BI Embedded

1. OBJETIVO O objetivo deste documento é definir a arquitetura referência para utilização do serviço Power BI Embedded na CAIXA, bem como, fluxos e softwares a serem utilizados. O documento também deve servir como um guia para direcionar a tomada de decisões sobre quando utilizar o serviço.

2. ARQUITETURA DO POWER BI EMBEDDED

![Imagem](<./imagem/index-imagem-114.png>)

Descrição da imagem - [./imagem/index-imagem-114.md](<./imagem/index-imagem-114.md>)

1. CONCEITOS O [Power BI SERVICES]{.underline} é uma coleção de serviços de software, aplicativos e conectores que trabalham juntos para transformar suas fontes de dados não relacionadas em informações coerentes, visualmente envolventes e interativas. O [Power BI Desktop]{.underline} é um aplicativo gratuito que pode ser instalado no computador local e que permite que você se conecte aos seus dados, transforme-os e visualize-os. Com o Power BI Desktop, você pode se conectar a várias fontes de dados diferentes e combiná-las (geralmente chamado de modelagem) em um modelo de dados. O [Power BI Embedded]{.underline} é uma solução de análise, no modelo de PaaS (plataforma como serviço), por capacidade, que permite aos autores de conteúdo inserir relatórios e dashboards em um aplicativo ou páginas web para seus usuários. Ele hospeda uma página web que poder embutido em outras páginas ou aplicativos e não obriga a utilização de licenças por usuário ou autenticação deles para que consigam visualizá-las. [Espaço de Trabalho]{.underline} (Workspace) são locais para compartilhar e criar coleções de painéis, relatórios, conjuntos de dados e relatórios paginados. Usuários licenciados (PBI PRO) possuem um Espaço de Trabalho pessoal e o Administrador do Power Bi Services poderá criar Espaços de Trabalho para os sistemas.

2. ATORES [USUÁRIO INTERNO]{.underline} é um usuário com licenças do tipo POWER BI PRO que é capaz de acessar o relatório compartilhados de outros usuários internos e capaz de publicar relatórios no "Espaço de Trabalho" e Power BI Embedded. [AUTOR DE CONTEÚDO]{.underline} é um usuário interno que através da ferramenta Power BI Desktop é capaz de criar relatórios conectando várias fontes de dados e criar painéis e visualizações. [USUÁRIO EXTERNO]{.underline} é um usuário externo à organização que atua apenas na leitura dos relatórios e não necessita de licenças de Power BI e nem de autenticação no serviço. [ADMINISTRADOR DO POWER BI SERVICES]{.underline} é um usuário interno com perfil de administração no serviço de Power BI e é o responsável por incluir os grupos de acesso ao serviço, criar os "Espaços de Trabalho" para os sistemas que serão o repositório para a publicação dos relatórios no Power BI Embedded. [ADMINISTRADOR DO AZURE]{.underline} é um usuário interno com perfil de administração no portal Azure e é responsável pela alocação de recursos dentro da subscrição do Power BI Embedded.

3. LICENÇA NECESSÁRIA [Power BI Pro]{.underline} é uma licença individual de usuário que permite que eles leiam e interajam com relatórios e painéis publicados por outras pessoas no serviço do Power BI. Os usuários com esse tipo de licença podem compartilhar conteúdo e colaborar com outros usuários do Power BI Pro. Somente os usuários do Power BI Pro podem publicar ou compartilhar conteúdo com outros usuários ou consumir conteúdo criado por outros usuários

4. CENÁRIO DE ADOÇÃO O PBI Embedded deverá ser utilizado para a publicação de relatórios em que o público-alvo seja externo à organização e que não tenha acesso a uma licença do Power BI. Poderá ser utilizado em páginas web ou em aplicativos móveis, respeitando a classificação da informação #PUBLICO, conforme definição do OR016. Essa arquitetura de referência não é recomendada para a apresentação de relatórios para um público interno.

5. IMPLANTAÇÃO EM PRODUÇÃO O arquiteto da solução apresenta a demanda com a necessidade de publicação de relatório com acesso externo. O capítulo de arquitetura avalia a pertinência e sugere a melhor solução de publicação de relatórios. Após a indicação da solução Power BI Embedded, o arquiteto da solução deverá abrir uma requisição para a execução das seguintes atividades: O Administrador do Azure irá alocar um recurso de capacidade para o sistema utilizar o Power BI Embedded. Esse recurso ficará dentro do Grupo de recursos da Subscrição indicada por ele. Por meio de uma requisição do serviços.caixa será criado um grupo de segurança (Active Directory) para o gerenciamento dos usuários internos, que utilizarão o Power BI Embedded, através do [http://gerenciamentogrupos.caixa](http://gerenciamentogrupos.caixa) . O Administrador do Serviço do Power BI cadastrará o grupo de segurança (Active Diretory) na configuração "Publicar na Web". O Administrador do Serviço do Power BI criará um "Espaço de Trabalho" para o sistema, com capacidade disponibilizada na subscrição liberada pelo Administrador do Azure. O AUTOR DE CONTEÚDO poderá publicar no "Espaço de Trabalho" o relatório criado no Power BI Desktop. Os relatórios presentes no "Espaço de Trabalho" do sistema precisarão ser publicados na Web para que fique disponível para acesso pela internet.

6. CONSIDERAÇÕES E LIMITAÇÕES Há suporte para o recurso Publicar na Web na grande maioria das fontes de dados e relatórios do serviço do Power BI. No entanto, atualmente, **[não]{.underline}** há suporte nem disponibilidade para os seguintes tipos de relatórios no recurso Publicar na Web: Relatórios que usam qualquer fonte de dados de Conexão Dinâmica, incluindo Tabulares do Analysis Services hospedados localmente no Analysis Service Multidimensional e o Azure Analysis Services. Relatórios que usam um conjunto de dados compartilhado, armazenado em um espaço de trabalho diferente daquele do relatório. Relatórios em um espaço de trabalho no qual você não é um membro de edição. Atualmente, não há suporte para os visuais do \"R\" nem do Python nos relatórios Publicar na Web. Exportação de dados de visuais em um relatório que foi publicado na Web. Relatórios que contêm medidas DAX no nível do relatório. Modelos de consulta de dados de logon único, incluindo modelos compostos em conjuntos de dados Power BI ou Azure Analysis Services. Os administradores podem bloquear o acesso à Internet pública. Nesse caso, a opção Publicar na Web está esmaecida para o seu locatário no portal de administração do Power BI.
