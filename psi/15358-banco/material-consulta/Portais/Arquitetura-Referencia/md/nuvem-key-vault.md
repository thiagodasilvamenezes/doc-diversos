# Key Vault

## Conceito

1. O Azure Key Vault é um serviço de nuvem para armazenar e acessar segredos de maneira segura.

2. Um segredo é qualquer coisa a qual se deseja controlar o acesso, como chaves de API, senhas, certificados ou chaves criptográficas.

3. O serviço do Key Vault oferece suporte a dois tipos de contêineres: cofres e pools HSM (módulo de segurança de hardware) gerenciados.

4. Os cofres oferecem suporte ao armazenamento de chaves, segredos e certificados apoiados por software e HSM.

5. Os pools HSM gerenciados oferecem suporte apenas a chaves apoiadas por HSM.

6. **HSM** O Hardware Security Module (HSM) é um dispositivo de criptografia baseado em hardware que fornece funções criptográficas para geração e armazenamento de chaves criptográficas simétricas e assimétricas em infraestruturas de chaves públicas.

7. **Resource group** Trata-se de um contêiner que mantém os recursos relacionados de uma solução do Azure. O grupo de recursos pode incluir todos os recursos para a solução ou apenas os recursos que se deseja gerenciar como um grupo.

8. **Entidade de Segurança** É uma entidade de segurança do Azure usada por aplicativos criados pelo usuário, serviços e ferramentas de automação para acessar recursos específicos do Azure. Ela funciona como uma "identidade do usuário" (nome de usuário e senha ou certificado) com uma função específica e permissões rigidamente controladas. Uma entidade de segurança realiza somente ações específicas, ao contrário de uma identidade de usuário geral. Ela melhora a segurança caso conceda-se apenas o nível mínimo de permissão necessário para executar as tarefas de gerenciamento. Uma entidade de segurança usada com um aplicativo ou serviço é chamada de entidade de serviço.

## Premissas

1. Senhas, arquivos de configuração que contenham senhas, e demais fatores de autenticação em sistemas devem ser protegidos no armazenamento e na transmissão, com criptografia implementada pelos próprios sistemas que geram a informação e/ou pelas ferramentas de suporte envolvidas, como servidores de aplicação, sistemas gerenciadores de bancos de dados, serviços de diretórios e ferramentas de transferência de dados.

2. Todo o tráfego resultante de acessos administrativos a produtos ou serviços de rede deve ser cifrado.

3. Todos os processos de autenticação de produtos ou serviços de rede devem ocorrer sob criptografia.

4. Deve-se utilizar hardwares próprios (HSM) para a geração e o armazenamento seguro de chaves criptográficas simétricas e chaves privadas assimétricas.

## Funções do Key Vault

1. Gerenciamento Gerenciamento de segredos -- O Key Vault deve ser usado para armazenar com segurança e controlar o acesso a tokens, senhas, certificados, chaves de API e outros segredos. Gerenciamento de chaves -- O Key Vault permite criar e controlar as chaves de criptografia. Gerenciamento de certificado -- O Azure Key Vault permite provisionar, gerenciar e implantar certificados de protocolo TLS/SSL públicos e privados para uso com o Azure e seus recursos internos conectados.

2. Centralização dos segredos do aplicativo O armazenamento centralizado de segredos do aplicativo no Azure Key Vault permite que se controle sua distribuição. O Key Vault reduz a probabilidade de os segredos serem vazados acidentalmente, e elimina a necessidade de inserir informações de segurança como parte do código. Por exemplo, a string de conexão com o banco de dados não pode ser inserida no código do aplicativo, deve ser armazenada com segurança no Key Vault. Os aplicativos acessam com segurança as informações necessárias usando URIs. Esses URIs permitem que os aplicativos recuperem versões específicas de um segredo, não há necessidade de escrever código personalizado para proteger as informações de segredo armazenadas no Key Vault.

3. Armazenamento de segredos e chaves com segurança O acesso a um cofre de chaves requer a devida autenticação e autorização antes de um usuário ou um aplicativo obter acesso, a autenticação estabelece a identidade do usuário e a autorização determina as operações que ele tem permissão para executar. A autenticação é feita pelo Azure Active Directory. A autorização pode ser feita por meio do controle de acesso baseado em função do Azure ou da política de acesso do Key Vault. Os Azure Key Vaults são protegidos por software ou, com a camada do Azure Key Vault Premium, protegidos por hardware por HSMs. Para situações que exijam garantia extra, é possível importar ou gerar chaves em HSMs. Monitoração do acesso e uso É possível a monitoração das atividades no key vault (o log dos cofres de senha deve ser habilitado). Administração simplificada dos segredos do aplicativo O Key vault organiza e simplifica a administração dos segredos do aplicativo por meio de: Remoção da necessidade de conhecimento interno sobre Módulos de Segurança de Hardware. Escalonamento vertical rápido para atendimento de regras de negócio. Replicação do conteúdo do key vault para dentro de uma região para uma região secundária (necessidade de ambas serem no Brasil). Separação dos segredos do aplicativo. Os aplicativos acessam apenas o cofre que eles têm permissão para acessar e podem estar limitados a executar operações específicas. Visão do gerenciamento de cofres e segredos As melhores práticas para o gerenciamento de cofres e segredos contemplam:

4. Configuração e armazenamento -- O Key Vault fornece armazenamento seguro de segredos, como senhas e cadeias de conexão de banco de dados.

5. Rotação de segredos -- Muitas vezes os segredos são armazenados na memória do aplicativo como variáveis de ambiente ou parâmetros de configuração.

6. O Key vault possibilita a rotação automática desses segredos dentro da uma periodicidade pré estabelecida.

7. Acesso e Isolamento de redes -- O key vault reduz a exposição dos cofres especificando quais endereços IP tem acesso a eles.

8. Monitoramento -- O key vault permite a ativação do registro de logs para possibilitar a monitoração do acesso aos segredos.

9. Backup e proteção contra limpeza -- Possibilita a proteção contra a exclusão mal-intencionada ou acidental dos segredos.

10. **Autenticação** Opções de autenticação: Quando um cofre de senhas é criado, ele é automaticamente associado ao locatário do Azure Active Directory da assinatura. O acesso ao key vault pode ser feito de 3 maneiras: Somente aplicativo: o aplicativo representa uma entidade de serviço ou uma identidade gerenciada. Essa ID é o cenário comum para aplicativos que periodicamente precisam acessar certificados, chaves ou segredos do cofre de chaves. Somente usuário: O usuário acessa o cofre de chaves de qualquer aplicativo registrado no locatário. Pode ser feito via portal ou Azure powerShell. Application-Plus-User (id composta): o usuário é solicitado acessar o cofre de chaves de um aplicativo específico e o aplicativo deve usar o fluxo de autenticação para representar o usuário. Para que esse cenário funcione o applicationID e o objectID devem ser especificados na política de acesso.

11. **Criptografia de dados em Trânsito** O Azure Key Vault impõe o protocolo TLS (Transporte Layer Security) para proteger os dados quando eles estão viajando entre o Azure Key Vault e os clientes. O TLS fornece uma autenticação forte, privacidade de mensagem integridade (habilitando a detecção de adulteração, interceptação e falsificação de mensagens), interoperabilidade, flexibilidade de algoritmo e facilidade de implantação e uso. A documentação referente a criptografia está prevista no seguinte endereço: [http://arquiteturati.caixa/arquitetura_referencia/22.10/seguranca/criptografia/#1-hsm-vault-e-icsf](http://arquiteturati.caixa/arquitetura_referencia/22.10/seguranca/criptografia/#1-hsm-vault-e-icsf)

## Indicações de uso

1. Todas as aplicações em nuvem (Azure) que contenham algum tipo de autenticação ou segredo gerenciado.

2. Por padrão as chaves serão protegidas por software, mas poderão ser protegidas por HSM conforme decisão da SUART tendo em vista o custo e a criticidade dos dados envolvidos. A definição do tipo de contêiner será realizada no momento da definição de arquitetura da aplicação.
