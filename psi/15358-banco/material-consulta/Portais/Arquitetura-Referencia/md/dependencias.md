# Boas práticas no gerenciamento com MAVEN

## Boas práticas

Ao gerenciarmos as dependências de nossos projetos com o Maven, já nos é oferecida uma solução de “convenção sobre configuração”, porém ainda é aconselhável que um cojunto de boas práticas sejam seguidas de forma a facilitar e padronizar o gerenciamento dos projetos MAVEN.

- Utilizar escopo provided para todas as dependências que são fornecidas pelo ambiente de execução da aplicação. (Bibliotecas instaladas no servidor de aplicação não devem ser empacotadas com a aplicação. Exceções a essa regra devem ser bem avaliada, pois em virtude do conflito no classloader, é preciso ajustar a configuração do projeto para que ele trabalhe com o modo de carregamento 'PARENT_LAST' que faz com que o carregamento das bibliotecas de aplicação aconteça antes do carregamento das bibliotecas do servidor)

- No caso de projetos multi módulos, utilizar a seção **"dependencyManagement"** do projeto PAI para declarar todas as dependências do projeto com suas versões e um escopo padrão. Isso torna mais simples o processo de gerenciamento das dependências por centralizar todas em um mesmo lugar. Nos projetos filhos declare apenas o groupID e artifactID das dependências necessárias.

- Uma outra forma de tornar o gerenciamento das dependências centralizado é criar um projeto do tipo **'BOM'** que declare todas as dependências e plugins padrões utilizados por todos os projetos (ou na maioria deles). Dessa maneira, os projetos importariam apenas a dependência desse projeto **'BOM'** mantendo todas as versões de dependências padronizadas. BOM é um tipo especial de POM que é usado para controlar as versões das dependências de um projeto e fornecer um local central para definir e atualizar essas versões.

- Usar propriedades para definir as versões de dependência. Dessa forma, você pode obter uma visão geral de todas as versões que estão sendo usadas, sem ter que rolar por várias páginas de seções de dependência.

- Usar o plug-in dependency:analyze para verificar se há dependências desnecessárias ou dependências declaradas, mas não usadas no projeto.

- Usar o plug-in dependency:tree para verificar a árvore de dependências do projeto a fim de encontrar possíveis conflitos em dependências transitivas

- Sempre que for necessário criação de ações customizadas para o MAVEN, escrever seu próprio código deve ser a última alternativa, sempre de preferência para plugin que façam a ação requerida.

- Durante o desenvolvimento, se possível use sempre versões SNAPSHOT: Elas reduzem a quantidade de espaço em disco usado pelo Nexus. Eles reduzem a frequência das mudanças que os projetos dependentes.

- Tente evitar o uso de propriedades herdadas. Os desenvolvedores podem facilmente esquecer que uma determinada propriedade é usada por um POM filho e alterar o valor quebrando a compilação.

- Não use referências obsoletas como ${artifactId} ou ${pom.artifactId}. Use a nova sintaxe ${project.artifactId}.
