# Backup Multiplataforma

**Importante:** Essa arquitetura de referência se encontra em fase de prospecção e não possui nenhum indicativo de uso geral pelas equipes.

**Assunto:** Hardware Multiplataforma

**Solução:** Backup Multiplataforma

**Software (s):** DELL POWER PROTECT ENTERPRISE EDITION

**Hardware (s):** DELL DATA DOMAIN DD9900

**Fabricante (s):** DELL/EMC

**Objetivo:** Apresentar as informações referentes a nova arquitetura de referência do ambiente de backup multiplataforma, com o objetivo de fornecer uma visão geral da infraestrutura de *hardware* que irá suportar esta nova solução.

## Formalização SUART

1. O que será apresentado neste documento é a nova arquitetura que será usada para atender as demandas de backup dos plataformas open (x86) e intermediaria (SPARC).

2. A nova arquitetura da solução de backup open foi definida por meio do RTC: **19415434.**

3. As justificativas para prospectar uma nova solução de backup foram: Descontinuidade da fitoteca ORACLE SL 8500 pelo seu fabricante, juntamente com os drivers e cartuchos T10K. A solução de backup atual da CAIXA já não atende toda a demanda de backup exigida, além de limitação de funcionalidades que hoje são necessárias e o TSM não possui. Complexidade no gerenciamento devido a existência de muitos clusters de TSM (19 no total) e cada um sendo administrado de forma isolado.

## Topologia da Arquitetura

1. Abaixo segue a topologia macro da nova arquitetura de Backup multiplataforma da CAIXA, que serão instaladas nos datacenters CTC e DTC com seus componentes e suas interconexões que compõe a solução de backup.

## Características da Arquitetura

1. A nova arquitetura de backup para o ambiente multiplataforma ( *Open e Sparc)* que foi especificada será composta pelos seguintes componentes: **Appliance de Backup Camada 1** A camada 1 ou camada de curta retenção, foi especificada com o objetivo de armazenar os dados de backup com retenção de até 30 dias. É composta por servidores customizados para executar as funcionalidades de backup e restore, estes equipamentos são conhecidos como appliances e em algumas soluções são os responsáveis por executar o software de backup, armazenar o banco de dados com informações de políticas e ainda os dados já protegidos pela solução. São nestes appliances que os dados de backup ficam armazenados por até 30 dias, após este prazo os dados são movidos automaticamente conforme definido em política de backup para os equipamentos que compõe a camada 2 que é a camada de longa retenção, ainda existe a possibilidade de estes dados de longa retenção serem enviados para nuvem pública caso venha a existir esta definição. **Appliance de Backup Camada 2** Também chamada de camada de longa retenção, porque o seu objetivo é armazenar os dados de backup com retenção superior a 30 dias, e poderá ser composta de duas formas a saber: **Applicance de backup --** equipamentos com alta densidade de armazenamento composto principalmente por discos magnéticos e dotados de tecnologias de redução de dados como a compressão e desduplicação. **Object Storage** - são storages que armazenam os arquivos em forma de objetos, possuem funcionalidades de desduplicação o que reduz a quantidades de objetos armazenados aumentando assim a sua capacidade final de armazenamento, são compatíveis com o armazenamento de objetos utilizando os protocolos S3, SWIFT e REST que são utilizados nos principais serviços de armazenamento em cloud pública (AWS e AZURE). **Software de Backup** O software da nova solução ainda não pode ser definido uma vez que a licitação para contratação da nova solução ainda não foi finalizada. **Clientes de Backup** São servidores físicos ou virtuais executando os sistemas operacionais Windows, Linux, Unix e Vmware, bancos de dados ORACLE, DB2, PostGrees e MS SQL, servidores de e-mail do Exchange entre outros e que se conectam aos Appliances de camada 1 para enviar arquivos para serem feitos backups e armazenados nos Appliances que posteriormente são transferidos para os Appliances ou Object Storage da camada 2 para serem arquivados pelo período determinado na política de backup aplicada a cada cliente de backup. **Consoles de Administração** São as consoles de gerenciamento do software e dos hardwares da solução de backup. É através destas consoles que são criadas e gerenciadas as políticas de backup e as configurações dos clientes de backup. Para a nova solução de backup todos os equipamentos de todos os sites deverão ser administrados por meio de uma única console de administração, simplificando o gerenciamento para as equipes de operação.

## Principais Recomendações de Uso

1. A nova solução de backup deve ser utilizada para atender todas as demandas de backup existentes na CAIXA para as plataformas Open (x86) e distribuída (SPARC).

2. Backup de todas as bases de dados em uso na CAIXA como Microsoft SQL Server, DB2, Portgress e Caché.

3. Backup dos diretórios de aplicações em servidores Web Server.

4. Backup das bases e Logs de todos os servidores de Active Director.

5. Backup das bases e Logs de todos os servidores de Sharepoint.

6. Backup de servidores de arquivos, notebooks e desktops.

7. Backup das máquinas virtuais (VM) dos ambientes Vmware e Hyper-V.

8. Backup de longa retenção para a solução de banco de dados ORACLE Exadata, na qual o ZDRLA será a camada de curta retenção e a nova solução de backup será a camada de longa retenção.

## Glossário

1. Controladora -- É a unidade autônoma contendo processamento, memoria, cache, portas de acesso a *front-end* e *back-end* e é responsável pelo gerenciamento, controle, acesso a discos, proteção, compressão e desduplicação entre outras tarefes importantes executadas em um subsistema de discos.

2. CIFS ( *Common Internet File System* ) -- É um protocolo de rede da camada de aplicação usado principalmente para fornecer acesso compartilhado a arquivos, impressoras e portas seriais e comunicações diversas entre nós sobre uma rede.

3. DAE ( *Disk Array Enclousure* ) -- É um modulo exclusivo para acomodação de discos ou SSDs e as controladoras são conectadas a ela por meio das portas de *back-end* que podem ser com tecnologia SAS, *Infiniband* ou *Ethernet* com RDMA.

4. HDD ( *Hard Disk Drive* ) -- É uma unidade de disco rígido mais comumente chamado de HD que usa pratos magnéticos giratórios e um cabeçote móvel de leitura/gravação para acessar dados.

5. HDFS (Hadoop Distributed File System) -- É um sistema de arquivos distribuído que armazena dados em máquinas dentro do cluster, sob demanda, permitindo uma largura de banda muito grande em todo o cluster.

6. *Infiniband* - É uma arquitetura de rede multifuncional de alto desempenho baseada em *switch* , geralmente chamado de \" *fabric* \". O *InfiniBand* (abreviado como \"IB\") foi projetado para uso em redes de armazenamento (SAN) ou em redes de cluster. Tornou-se um padrão líder em computação de alto desempenho.

7. Cache -- É uma porção de armazenamento em tecnologia ultra rápida e de baixa latência geralmente em memória do tipo DRAM ( *Dynamic Random Access Memory* ) ou a mais nova tecnologia SCM ( *Storage Class Memory* ) e ela serve para acelerar a leitura e escrita dos dados pelos clientes do *storage* , por ser mais rápida do que fazer o acesso direto ao disco ou SSD.

8. DWDM (Dense Wavelength Division Multiplexing ou Multiplexação Densa por Divisão de Comprimento de Onda) -- é uma tecnologia que, basicamente, usa diversos lasers para transmitir múltiplos comprimentos de onda de luz simultaneamente, multiplexando os sinais em uma única fibra óptica, e na CAIXA a utilizamos para criar uma rede de baixa latência que interliga os dois datacenters (DTC e CTC).

9. LAN (Local Area Network) -- É uma rede de alta velocidade (10 Gbps) e baixa latência (da ordem de milissegundos) que utiliza o protocolo Ethernet e é utilizada para fazer a comunicação entre os clientes de backup e os Clusters de TSM e também para a comunicação entre os Clusters de TSM e os Storages ISILON.

10. NAS ( *Network Attached Storage* ) -- É um subsistema de armazenamento em disco conectado a uma rede TCP-IP que possibilita o armazenamento e a recuperação de dados de um local centralizado para usuários autorizados da rede e clientes de sistemas operacionais heterogêneos.

11. NFS ( *Network File System* ) - É um sistema de arquivos distribuídos desenvolvido pela Sun Microsystems, a fim de compartilhar arquivos e diretórios entre computadores conectados em uma rede TCP-IP.

12. Node -- É a unidade autônoma contendo processamento, memoria, cache, portas de acesso a *front-end* e *back-end* e é responsável pelo gerenciamento, controle, acesso a discos, proteção, compressão e desduplicação entre outras tarefes importantes executadas em um subsistema de discos.

13. *Back-End* -- São as portas utilizadas pelos Nodes ou controladoras em uma rede interna privada responsável pelo acesso aos dados, controles e proteção dos discos, utilizando protocolos como *Ethernet* , *Infiniband* ou SAS.

14. *Front-End* -- São as portas *Ethernet* 10 Gbps utilizadas para conectar os *storages* aos *switches* da rede LAN, e são as portas por onde trafegam os dados entre os *storages* e os servidores.

15. Processadores -- São responsáveis por executar todas as instruções de acesso a discos, controles, proteções, compressão e desduplicação entre outras tarefas executadas pelas controladoras.

16. REST -- Representational State Transfer (REST), em português Transferência Representacional de Estado é uma arquitetura de software que define um conjunto de regras para a criação de web services, ele permite a interoperabilidade entre sistemas operacionais diferentes, ele fornece algumas operações que são executadas atraves do protocolo HTTP que são eles: GET, HEAD, POST, PUT, PATCH, DELETE, CONNECT, OPTIONS e TRACE.

17. SAN (Storage Area Network) -- É uma rede de alta velocidade (16 Gbps) e baixíssima latência (da ordem de microssegundos), que utiliza como meio físico a fibra optica e o protocolo Fiber Channel e é utilizada para fazer a comunicação entre os Clusters de TSM e os Storages VMAX e as Fitotecas SL8500.

18. SAS ( *Serial Attached SCSI* ) - É a evolução tecnológica do protocolo SCSI com mais performance e flexibilidade, é uma tecnologia de transmissão de baixo custo, *full-duplex* (transmite e recebe dados ao mesmo tempo) e com taxas de transferência de 3, 6 ou 12Gbps (gigabits por segundo).

19. SCM ( *Storage Class Memory* ) -- é um novo tipo de memória que utiliza na sua criação memorias DRAM e memória Flash, é usada para acelerar o acesso de leitura e gravação nos *storages* mais modernos e de alta performance.

20. SMB ( *Server Message Block* ) -- É um protocolo de rede da camada de aplicação usado principalmente para fornecer acesso compartilhado a arquivos, impressoras e portas seriais e comunicações diversas entre nós sobre uma rede.

21. SSD ( *Solid State Drive* ) -- É um tipo de dispositivo de armazenamento de dados mais novo e rápido que armazena dados em chips de memória que podem ser acessados instantaneamente.

22. *Storage* -- É um subsistema de armazenamento em disco podendo utilizar discos mecânicos (HDDs) ou drives de estado sólido (SSDs), vejamos abaixo os principais componentes de um s *torage* .

23. S3 (Amazon Simple Storage Service) - É um serviço de armazenamento de objetos construído para armazenar e recuperar qualquer volume de dados de qualquer local que oferece escalabilidade, disponibilidade de dados, segurança e performance.
