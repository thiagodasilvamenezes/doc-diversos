# GATEWAY DE DADOS LOCAIS

## ARQUITETURA DO GATEWAY DE DADOS LOCAIS

![Imagem](<./imagem/index-imagem-164.png>)

Descrição da imagem - [./imagem/index-imagem-164.md](<./imagem/index-imagem-164.md>)

1. O gateway de dados local atua como uma ponte, proporciona a transferência de dados rápida e segura entre dados locais, que são dados que estão na rede local ( *on premises* ), e vários serviços em nuvem da Microsoft.

2. Ao usar um gateway, a CAIXA pode manter os bancos de dados e outras fontes de dados em sua rede local ( *on premises* ), ao mesmo tempo em que usa esses dados locais com segurança em serviços de nuvem.

## FONTES DE DADOS

1. O gateway de dados local permite que várias bases de dados locais sejam acessadas por vários serviços em nuvem da Microsoft que incluem Microsoft SQL Server, Microsoft SQL Analysis Services, Arquivos de dados e SharePoint On premises.

## SERVIÇOS EM NUVEM

1. O gateway de dados local permite que vários serviços em nuvem da Microsoft acessem bases locais que incluem Power BI, Power Apps, Power Automate e Azure Analysis Services.

2. Cada serviço em nuvem da Microsoft possui uma lista de fontes de dados que é capaz de se conectar, sendo que apenas o serviço Power BI Online possui conectores sem custos adicionais.

3. A lista completa de fontes do Power BI, encontra-se neste link: [https://learn.microsoft.com/pt-br/power-bi/connect-data/power-bi-data-sources](https://learn.microsoft.com/pt-br/power-bi/connect-data/power-bi-data-sources) Vale ressaltar que a configuração de fonte de dados é realizada pelo administrador do serviço do Power BI, com a autenticação realizada por conta de serviço com acesso à base de dados.

## CLUSTER DO GATEWAY

![Imagem](<./imagem/index-imagem-165.png>)

Descrição da imagem - [./imagem/index-imagem-165.md](<./imagem/index-imagem-165.md>)

1. O Gateway é composto por um servidor virtualizado (Microsoft Windows Server) com acesso à nuvem Microsoft.

2. É recomendado que os administradores de gateway criem um cluster para que se evite um ponto único de falha para o acesso a dados local. Um cluster garantirá que se o gateway primário não estiver disponível, as solicitações de dados serão encaminhadas para o segundo gateway que o administrador adicionar ao cluster e assim por diante. Esse recurso visa garantir a redundância do Gateway.

## PAPEIS E RESPONSABILIDADES

1. ADMINISTRADOR: Será o responsável por gerenciar o gateway local, verificar sua disponibilidade e capacidades. Também, é o administrador que irá configurar o gateway local nos serviços online.

2. GESTOR OPERACIONAL: É a área responsável pela definição dos usuários que poderão utilizar o gateway, bem como quais fontes de dados trafegarão por ele.

3. USUÁRIO CAIXA: É o usuário que consome as fontes de dados que trafegam pelo gateway local. Necessita de licenciamento conforme serviço da nuvem Microsoft. Por exemplo, um designer de Power BI necessita de licença Power BI PRO para a publicação de relatórios compartilháveis no serviço online.

4. USUÁRIO DE SERVIÇO: É a conta de serviço que tem acesso à base de dados, sendo de gestão do Gestor Operacional do gateway. Deverá ser autenticada pelo Administrador do serviço em nuvem Microsoft.

## CENÁRIO DE ADOÇÃO

1. O gateway de dados locais deverá ser utilizado para a conexão de fontes de dados locais ( *on* *premises* ) com os serviços em nuvem da Microsoft, conforme definições da gestão operacional do gateway local.

## CONSIDERAÇÕES

1. O Power Apps e o Power Automate dão suporte a operações de leitura e gravação por meio do gateway: Para operações de gravação o gateway tem um limite de carga de 2 MB. Para operações de leitura o gateway tem um limite de solicitação de 2 MB e um limite de resposta de dados compactados de 8 MB. A URL para a solicitação GET tem um limite de 2.048 caracteres. Ao usar o gateway com o Power BI no Modo de Consulta Direta, haverá um limite de resposta de dados descompactados de 16 MB. Consultas como atualizações do Power BI e do Azure Analysis Services podem retornar grandes quantidades de dados das bases. Para essas consultas, os dados são armazenados temporariamente no computador do gateway. Esse armazenamento de dados continua até que todos os dados sejam recebidos da fonte de dados. Depois, os dados são retornados ao serviço de nuvem. Esse processo é chamado de spool.

## Glossário

1. Gateway: o aplicativo de gateway de dados local instalado em um servidor.

2. Servidor de gateway: um servidor Windows (máquina virtual ou computador/servidor físico) que tem o aplicativo de gateway de dados local instalado.

3. Cluster de gateway: um conjunto de gateways que funcionam em conjunto (e podem ter balanceamento de carga).

4. Membro do gateway: um gateway que faz parte de um cluster de gateway.
