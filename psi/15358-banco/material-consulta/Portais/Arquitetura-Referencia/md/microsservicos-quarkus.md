# Microsserviços com Quarkus

Quarkus é um framework Java para desenvolvimento de aplicações cloud-native. Ele é baseado no MicroProfile, um conjunto de especificações open source que fornecem funcionalidades comuns para aplicações Java.

Quarkus é uma boa escolha para desenvolvimento de microsserviços por uma série de motivos, incluindo:

- Projetado para microsserviços: O Quarkus foi projetado desde o início para ser usado em microsserviços. Ele fornece recursos e funcionalidades específicos para esse tipo de arquitetura, como: Injeção de dependências: O Quarkus usa injeção de dependências para conectar microsserviços entre si. Conexão: O Quarkus fornece suporte para conexão a bancos de dados, serviços de mensagens e outros recursos externos, o que facilita a comunicação entre microsserviços. Segurança: O Quarkus fornece recursos de segurança integrados, que podem ser usados para proteger microsserviços. Testes: O Quarkus fornece recursos de teste integrados, que podem ser usados para testar microsserviços.

- Desempenho e escalabilidade: O Quarkus é projetado para ser executado em formato nativo, o que resulta em um aumento significativo no desempenho e na escalabilidade.

- Ecossistema: O Quarkus tem um grande ecossistema de extensions, que fornecem funcionalidades adicionais para desenvolvimento de aplicações Java.

## Arquitetura de referência

A padronização no processo de desenvolvimento traz uma gama de benefícios, como maior produtividade, curva de apendizagem diminuida, menor custo, etc. Como forma de uniformizar o desenvolvimento de soluções corporativas desenvolvidas com Quarkus, foi definido um conjunto mínimo diretrizes para o desenvolvimento de novas soluções.

### Quarkus Config

Quarkus Config é um sistema de configuração que permite que você configure as propriedades de suas aplicações Quarkus de forma centralizada. Ele é baseado no MicroProfile Config, um conjunto de especificações open source que fornecem um modelo consistente para configuração de aplicações Java.

Quarkus Config suporta várias fontes como variáveis de ambiente, propriedades do sistema ou mesmo sistemas de configuração distribuída. A ordem de prioridade pode ser ajustada conforme necessário.

#### Benefícios

- Configuração Centralizada: O Quarkus Config permite integrar-se com sistemas de configuração centralizada, como o ConfigMaps do Kubernetes ou até mesmo com soluções como o Consul.

- Configuração Dinâmica: O Quarkus Config permite atualizações dinâmicas, o que significa que as alterações feitas em uma configuração podem ser refletidas na aplicação em tempo real sem a necessidade de reiniciar.

- Segurança: Configurações sensíveis, como chaves e credenciais, podem ser armazenadas de forma segura e criptografada com o Quarkus Config, garantindo que dados críticos permaneçam protegidos.

O Quarkus Config utiliza o formato MicroProfile Config para suas configurações. Configurações podem ser definidas no arquivo application.properties:

```
app.message=Mensagem
```

Para acessar uma configuração no código, deve-se injetar a propriedade usando a anotação @ConfigProperty

```
@Inject @ConfigProperty("app.message", defaultValue="100")
String message;
```

#### Boas Práticas

- Modularizar as configurações: Mantenha configurações relacionadas agrupadas e bem documentadas. Isso facilitará a manutenção e compreensão do que cada configuração faz.

- Usar perfis: O Quarkus Config suporta a definição de perfis, como 'dev', 'prod', etc. Isso permite diferentes configurações para diferentes ambientes.

- Monitore suas configurações: Em um ambiente de produção, é importante monitorar e auditar as alterações nas configurações.

### Quarkus Fault Tolerance

O Quarkus Fault Tolerance é um conjunto de recursos que permitem que você as aplicações Quarkus sejam mais resilientes a falhas. Ele é baseado no MicroProfile Fault Tolerance, um conjunto de especificações open source que fornecem um modelo consistente para tolerância a falhas de aplicações Java.

O Quarkus Fault Tolerance implementa os principais padrões de resiliência:

- Circuit Breaker: Um circuito breaker é um mecanismo que protege sua aplicação de falhas de serviços externos. Ele funciona interrompendo o fluxo de solicitações para um serviço se o serviço estiver com falha. Deve ser usada a anotação **@CircuitBreaker**

- Retry: O retry é um mecanismo que permite que sua aplicação tente novamente uma solicitação que falhou. Ele é usado para lidar com falhas transitórias, como falhas de rede. Deve ser usada a anotação **@Retry**

- Fallback: O fallback é um mecanismo que permite que sua aplicação retorne um valor padrão se uma solicitação falhar. Ele é usado para lidar com falhas que não podem ser recuperadas. Deve ser usada a anotação **@Fallback**

- Timeout: Um timeout é um mecanismo que permite que sua aplicação desista de uma solicitação após um período de tempo especificado. Ele é usado para lidar com falhas que levam muito tempo para serem resolvidas. Deve ser usada a anotação **@Timeout**

- Bulkhead: Limita o número de threads que podem ser usados para executar um método ou classe. . Deve ser usada a anotação **@Bulkhead**

Para utilizar o Fault Tolerance com Quarkus, é necessário adicionar a dependência do MicroProfile Fault Tolerance. No seu arquivo pom.xml:

```

io.quarkus
</groupId>
<artifactId>
quarkus-smallrye-fault-tolerance
</artifactId>
</dependency>
```

### Quarkus Health Check

O Quarkus Health Check é um recurso que permite que você verifique o status de sua aplicação Quarkus. Ele é baseado no MicroProfile Health, um conjunto de especificações open source que fornecem um modelo consistente para health check de aplicações Java.

Quarkus Health Check oferece os seguintes tipos de Health Check:

- Liveness Check: Indica se o microserviço está em execução e em estado operacional. Se um serviço não estiver "vivo", ele pode ser reiniciado ou reparado. Deve ser configurado com a anotação **@Liveness** .

- Readiness Check: Indica se o microserviço está pronto para processar solicitações. Se não estiver pronto, ele não deve receber tráfego. Deve ser configurado com a anotação **@Readiness** .

```

</artifactId>
```

### Quarkus Metrics

O Quarkus Metrics é um recurso que permite que você colete métricas de sua aplicação Quarkus. Ele é baseado no MicroProfile Metrics, um conjunto de especificações open source que fornecem um modelo consistente para coleta de métricas de aplicações Java.

Quarkus Health Check oferece as seguintes métricas:

- Counter: Um counter é uma métrica simples que representa uma contagem acumulativa de um determinado evento ou operação. Ele é projetado para ser apenas incrementado, nunca reduzido. Esse tipo de métrica é útil para rastrear coisas como o número total de requisições feitas a um endpoint ou o total de mensagens processadas por uma fila. A anotação correspondente no MicroProfile Metrics para representar um counter é @Counted.

- Gauge: Diferente do counter, um gauge é uma métrica que pode variar livremente para cima ou para baixo, fornecendo uma medição instantânea de um valor específico em um determinado momento. Gauges são comumente utilizados para medir valores que naturalmente flutuam, como o uso atual de memória, o tamanho de uma fila ou o número de usuários ativos em um sistema. A anotação que você utilizaria para representar um gauge é @Gauge.

- Metered: A métrica metered fornece insights sobre a frequência de chamadas ou a taxa de solicitações a um determinado trecho de código. Isso pode ser útil para monitorar a taxa de chegada de novas conexões, pedidos ou mensagens em uma aplicação. A anotação @Metered é usada para definir essa métrica.

- Timed: Quando você quer entender quanto tempo uma operação ou requisição leva para ser concluída, você precisa de uma métrica timed. Isso permite aos desenvolvedores obter insights sobre a performance de partes específicas de sua aplicação, como a duração média de um método ou a duração de uma chamada de API. Use a anotação @Timed para rastrear essas métricas.

O Quarkus Metrics expõe métricas para Prometheus por padrão. Isso permite que ferramentas de monitoramento baseadas em Prometheus sejam usadas para monitorar a aplicação.

### OpenAPI

OpenAPI é uma especificação para APIs RESTful que fornece uma linguagem padrão e fácil de entender para definir APIs. Utilizando esta especificação, desenvolvedores, ferramentas de teste, e plataformas de integração podem compreender as capacidades de um serviço sem acessar seu código-fonte ou ver mais detalhes da implementação.

Quarkus traz uma implmentação de OpenApi que permite aos desenvolvedores gerar automaticamente documentação OpenAPI para seus endpoints. Ao adicionar esta extensão ao seu projeto, os metadados de seus endpoints são automaticamente escaneados e um documento OpenAPI é produzido.

Quarkus OpenAPI garante que a documentação esteja sempre atualizada com as últimas alterações do código. Esta abordagem "código como fonte da verdade" garante que a documentação seja sempre precisa, eliminando discrepâncias entre a documentação e a implementação real.

Para usar Open API no Quarkus, você precisa adicionar a seguinte dependência:

```
<dependency>
<groupId>
io.quarkus
</groupId>
<artifactId>
quarkus-smallrye-openapi
</artifactId>
</dependency>
```

Com a extensão habilitada, a documentação OpenAPI está disponível por padrão em /openapi. Além disso, Quarkus oferece uma interface gráfica através do Swagger UI, acessível em /swagger-ui, permitindo que desenvolvedores e stakeholders interajam e testem os endpoints diretamente pela interface.

### Quarkus Rest Client

O Quarkus REST Client é um recurso que permite que você consuma APIs RESTful de forma fácil e eficiente. O Quarkus REST Client é baseado no MicroProfile REST Client, um padrão open source que define uma API para consumir APIs RESTful.

Ao invés de lidar com lógicas HTTP complexas ou bibliotecas de terceiros, você define uma interface Java simples para representar o serviço RESTful remoto. Essa interface é depois injetada na sua aplicação, onde você pode chamar seus métodos como qualquer outro serviço Java.

Para usar Quarkus Rest Client, você precisa adicionar a seguinte dependência:

```
<dependency>
<groupId>
io.quarkus
</groupId>
<artifactId>
quarkus-rest-client
</artifactId>
</dependency>
```

```

quarkus.restclient.read-timeout=5000
quarkus.restclient.connect-timeout=5000
```

O Quarkus REST Client fornece uma série de anotações que podem ser usadas para personalizar o cliente RESTful. Essas anotações podem ser usadas para adicionar informações sobre os endpoints, operações, parâmetros, respostas e schemas do cliente RESTful.
