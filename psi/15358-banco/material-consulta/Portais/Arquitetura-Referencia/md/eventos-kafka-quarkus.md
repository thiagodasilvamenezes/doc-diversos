# Apache Kafka com Quarkus

O Quarkus fornece suporte para Apache Kafka através da estrutura SmallRye Reactive Messaging . Ele é baseado na especificação Eclipse MicroProfile Reactive Messaging 2.0, e utiliza CDI e orientado a eventos para fornecer um modelo de programaçao flexivle.

Para incluir o suporte ao Kafka, é necessário que seja incluída no projeto a extensão smallrye reactive message kafka, através de uma dependência no pom.xml do projeto, ou via CLI do quarkus.

```
<dependency>
<groupId>
io.quarkus
</groupId>
<artifactId>
quarkus-smallrye-reactive-messaging-kafka
</artifactId>
</dependency>
```

```
quarkus
extension
add
'smallrye-reactive-messaging-kafka'
```

## Configuração do conector Quarkus

O framework Smallrye Reactive Messaging suporta diferentes tipos de MOM's como Apache Kafka, AMQP, Apache Camel, JMS, MQTT, dessa forma ele emprega um vocabulário genérico que preisa ser convertido para as nomenclaturas de cada um do produtos suportados:

Os aplicativos(produtores/consumidores) enviam e recebem mensagens . Com o conector Kafka, uma mensagem corresponde a um registro Kafka .

As mensagens transitam nos canais (tópicos) . Os aplicativos se conectam aos canais para publicar e consumir mensagens. O conector Kafka mapeia canais para tópicos Kafka .

Os canais são conectados usando conectores . Os conectores são configurados para mapear mensagens de entrada para um canal específico (consumido pelo aplicativo) e coletar mensagens de saída enviadas para um canal específico. O conector que lida com Kafka é denominado smallrye-kafka.

Deve ser realizada uma configuração mínima no arquivo application.properties para habilitar o conector do kafka no projeto:

```
kafka.bootstrap.servers=localhost:9092 
mp.messaging.incoming.connector=smallrye-kafka 
mp.messaging.outgoing.connector=smallrye-kafka
```

## Produtores Kafka

O smallrye-reactive-messaging-kafka utiliza a anotação @Incoming para que as mensagems de um tópico sejam recebidas reativamente pela aplicação.

O envio de uma mensagem pode ser feito através de um Emmiter que retorna um CompletionStage com a informação de que a mensagem foi processada com sucesso ou com falha.

## Consumidores Kafka

O smallrye-reactive-messaging-kafka utiliza a anotação @Incoming para que as mensagems de um tópico sejam recebidas reativamente pela aplicação.

Existem várias formas de receber uma mensagem de um tópico com Quarkus.

- Através de um valor literal da mensagem. `@Incoming ( "topico1" ) public void consume ( double valor ) { }`

- Através de um objeto Mensagem `@Incoming ( "topico1" ) public CompletionStage < Void > consume ( Message < Double > msg ) { var metadata = msg . getMetadata ( IncomingKafkaRecordMetadata . class ). orElseThrow (); double price = msg . getPayload (); return msg . ack (); }`

- Através de um objeto consumer record `@Incoming ( "topico1" ) public void consume ( ConsumerRecord < String , Double > record ) { String key = record . key (); String value = record . value (); String topic = record . topic (); int partition = record . partition (); }`

- Através de um objeto Record `@Incoming ( "prices" ) public void consume ( Record < String , Double > record ) { String key = record . key (); String value = record . value (); }`

## Tratamento de erros

O conector Kafka suporta três estratégias de tratamento de erros:

- fail: falha na aplicação, não serão processados ​​mais registros (estratégia padrão).

- ignore: a falha é registrada, mas o processamento continua.

- dead-letter-queue: o registro é gravado em um tópico de mensagens mortas do Kafka.
