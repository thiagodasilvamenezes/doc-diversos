# Microsserviços com Spring

O Spring é um framework open source para a plataforma Java criado por Rod Johnson e descrito em seu livro "Expert One-on-One: JEE Design e Development". Trata-se de um framework não intrusivo, baseado nos padrões de projeto inversão de controle e injeção de dependência.

O Spring fornece uma série de recursos e abstrações que permitem que os desenvolvedores criem aplicações Java de forma rápida e eficiente. Esses recursos incluem:

- Inversão de controle: O Spring gerencia a dependência das classes em outras classes, eliminando a necessidade de os desenvolvedores codificarem manualmente essas dependências.

- Injeção de dependência: O Spring injeta as dependências necessárias nas classes, eliminando a necessidade de os desenvolvedores criarem objetos manualmente.

- Arquitetura de camadas: O Spring fornece um modelo de arquitetura de camadas que ajuda os desenvolvedores a organizar suas aplicações de forma lógica.

- Autenticação e autorização: O Spring fornece recursos de autenticação e autorização integrados, que podem ser usados para proteger aplicações.

- Transações: O Spring fornece suporte a transações, que pode ser usado para garantir a consistência dos dados.

- Testes: O Spring fornece recursos de teste integrados, que podem ser usados para testar aplicações.

## Spring Boot

O Spring Boot é um framework open source que facilita o desenvolvimento de aplicações Java. Ele é construído em cima do Spring Framework e faz parte do ecossitema Spring.

O Spring Boot pode ser usado em uma ampla variedade de cenários, incluindo:

- Aplicações de microsserviços: O Spring Boot pode ser usado para criar microsserviços independentes e escaláveis.

- Aplicações em nuvem: O Spring Boot é uma boa opção para aplicações que serão executadas na nuvem.

O Spring Boot se integra com o Spring Framework por meio de uma série de anotações e dependências. Essas anotações e dependências permitem que os desenvolvedores configurem e executem aplicações Spring com facilidade.

O Spring Boot simplifica o processo de configuração e execução de aplicações Spring. O Spring Boot fornece uma série de recursos e abstrações que permitem que os desenvolvedores criem aplicações Spring com rapidez e eficiência.

O Springboot juntamente com o Quarkus formam o conjunto de framework padrões para o desenvovimento de Microsserviços na plataforma Java.

## Arquitetura de referência

A padronização no processo de desenvolvimento traz uma gama de benefícios, como maior produtividade, curva de apendizagem diminuida, menor custo, etc. Como forma de uniformizar o desenvolvimento de soluções corporativas desenvolvidas com Spring Boot, foi definido um conjunto mínimo diretrizes para o desenvolvimento de novas soluções.

### Spring Boot DevTools

O Spring Boot DevTools é uma coleção de ferramentas que auxilia no desenvolvimento de aplicativos Spring Boot, oferecendo uma série de recursos que melhoram o ciclo de desenvolvimento. Essas ferramentas são destinadas a desenvolvedores e equipes de desenvolvimento para tornar o desenvolvimento de aplicativos mais eficiente e agradável.

#### Recursos e funcionalidades principais:

##### Reinicialização automática (Live Reload)

Uma das funcionalidades mais proeminentes do DevTools é a reinicialização automática do aplicativo durante o desenvolvimento. Quando você faz uma alteração no código-fonte do aplicativo e salva o arquivo, o DevTools detecta essa alteração e reinicializa automaticamente o aplicativo. Isso economiza tempo, pois você não precisa parar e iniciar manualmente o aplicativo sempre que fizer alterações.

##### Hot Swapping

Além da reinicialização automática, o DevTools permite que você faça hot swapping de código. Isso significa que você pode alterar o código-fonte de uma classe em execução e ver as mudanças refletidas imediatamente no aplicativo em execução, sem a necessidade de reinicialização completa.

##### Suporte para propriedades específicas do ambiente

O DevTools permite que você defina propriedades específicas do ambiente (como propriedades de configuração) que são usadas apenas durante o desenvolvimento. Isso simplifica a configuração do ambiente de desenvolvimento sem afetar o ambiente de produção.

##### Console remoto

O DevTools oferece um console remoto que permite interagir com seu aplicativo em execução. Isso pode ser útil para inspecionar o estado do aplicativo, executar comandos e depurar problemas em tempo real.

##### Desabilitação no ambiente de produção

O DevTools é projetado para ser usado apenas em ambientes de desenvolvimento. Quando você implanta seu aplicativo em um ambiente de produção, o DevTools é desativado automaticamente.

Sua configuração é automática, bastantando ao desenvolvedor adicionar a seguinte dependência ao projeto

```
<dependency>
<groupId>
org.springframework.boot
</groupId>
<artifactId>
spring-boot-devtools
</artifactId>
<scope>
runtime
</scope>
<optional>
true
</optional>
</dependency>
```

### Spring Boot Web

O spring Boot Web configura automaticamente uma gama de funcionalidades necessárias para o desenvolvimento de uma aplicação web ou microsserviço. O Spring Boot Web utiliza o Spring MVC como framework, realizando nele todas as configurações necessárias para tornar a aplicação funcional. Para adicioná-lo é necessário apenas incluir sua dependência no pom.xml

```
<dependency>
<groupId>
org.springframework.boot
</groupId>

spring-boot-starter-web
</artifactId>
```

O Spring Boot Web inclui um servidor embarcado como parte do artefato implantável. o Apache Tomcat é utilizado como servidor embarcado, porém é recomendado substituí-lo pelo servidor Jboss Undertow. Para realizar a substituição deve-se desabilitar o Apache Tomcat, para isso é necessário realizar a exclusão da dependencia transitiva do Apache Tomcat do Spring Boot WEB. ### Spring Boot Actuator

O Spring Boot Actuator fornece insights detalhados sobre o comportamento operacional de uma aplicação em produção, incluindo a saúde da aplicação, métricas, análises de memória, threads, variáveis de ambiente e muito mais. Ele possibilita essas interações por meio de endpoints HTTP ou beans JMX.

Para ativar o Spring Boot Actuator, basta adicionar sua dependência ao arquivo pom.xml do projeto.A

```
<dependency>
<groupId>
org.springframework.boot
</groupId>
<artifactId>
spring-boot-starter-actuator
</artifactId>
</dependency>
```

Uma vez incluída a dependência, vários endpoints se tornam disponíveis para serem consumidos no sistema.

O Spring Boot Actuator fornece um endpoint de descoberta que retorna links para todos os endpoints disponibilizados pelo Actuator. Esse endpoint de descoberta é definido pelo path '/actuator'

Alguns dos endpoints mais úteis do Spring Boot Actuator são:

- Health: O endpoint /actuator/health pode ser usado para verificar se a aplicação está funcionando corretamente. Por padrão o Actuator disponibiliza apenas o healthcheck de estado da aplicação. Para liberar todos os healthchecks, deve-se adicionar ao arquivo application.properties a seguinte propriedade: `management.endpoint.health.show-details = always`

- Metrics: O endpoint /actuator/metrics pode ser usado para coletar informações sobre o desempenho da aplicação, como o tempo de resposta das solicitações e o uso de memória.

- Info: O endpoint /actuator/info pode ser usado para obter informações sobre a configuração da aplicação, como a versão do framework e as dependências usadas.

- Env: O endpoint /actuator/env pode ser usado para obter informações sobre o ambiente de execução da aplicação, como as variáveis de ambiente e as propriedades do sistema.

Métricas e healthchecks adicionais podem ser incluídos por meio de dependências que são adicionadas ao projeto, ou podem ser criados pela equipe de desenvolvimento de acordo com a necessidade do projeto.

### Spring Config Properties

O Spring Boot permite que as configurações da aplicação sejam externalizadas podendo ser obtidas de uma variedade de fontes externas, o que inclui, arquivos de propriedades Java, arquivos YAML, variáveis ​​de ambiente e argumentos de linha de comando. Essa característica é extremamente útil, pois nos permite trabalhar com o mesmo código em ambientes diferentes.

O Spring acessa as propriedades dos arquivos de configuração externa através de injeção de dependência, qualquer chave cadastrada em um arquivo de configuração pode ser injetada em um bean do Spring.

Existem 3(três) formas de realizar essa injeção, que são:

- Anotação @Value: Permite realizar a injeção de propriedades simples.

- API Environment: Nesse cenário, apenas a classe Environment é injetada nos beans do Spring. O acesso as propriedades externalizadas é feito através dessa classe utilizando-se o método getProperty. Esse método possui duas versões, na primeira recebe o nome da propriedade a ser recuperada, na segunda, além do nome da propriedade, recebe um valor padrão caso a propriedade não seja encontrada.

- Anotação @ConfigurationProperties: Permite realizar a injeção de objetos complexos. Geralmente quando é necessário injetar várias propriedades, o código pode se tornar confuso e poluído se usarmos muitas anotações @Value, nesses casos, podemos agrupar todas as propriedades necessárias em um POJO e utilizar a anotação @ConfigurationProperties para injetar esse POJO com todas as propriedades já preenchidas do arquivo de configuração externo.

### Spring Boot Data JPA

Spring Boot Data JPA é um módulo do Spring Boot que fornece uma API de acesso a dados baseada no Java Persistence API (JPA). O JPA é uma especificação Java que define uma API para o acesso a dados em bancos de dados relacionais.

O Spring Boot Data JPA simplifica o desenvolvimento de aplicações Java que acessam dados em bancos de dados relacionais. Ele fornece uma API de acesso a dados de alto nível que é baseada no padrão Repository.

O Spring Boot Data JPA funciona criando uma implementação automática de uma interface Repository. A interface Repository define um conjunto de métodos que podem ser usados para acessar dados em um banco de dados relacional.

Para criar uma interface Repository, o desenvolvedor deve estender a interface Repository do Spring Data JPA. A interface Repository fornece um conjunto de métodos genéricos que podem ser usados para acessar dados em um banco de dados relacional.

Para usar o Spring Boot Data JPA, o desenvolvedor deve adicionar a dependência spring-boot-starter-data-jpa ao arquivo pom.xml do projeto.

```
<dependency>
<groupId>
org.springframework.boot
</groupId>
<artifactId>
spring-boot-starter-data-jpa
</artifactId>
</dependency>
```

Spring Boot Data JPA também requer que o desenvolvedor especifique as configurações do banco de dados no arquivo application.properties.

```
spring.datasource.url=jdbc:[driver]://[servidor]:[porta]/[banco]
   spring.datasource.username=[usuario]
   spring.datasource.password=[senha]
   spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.[dialeto]
   spring.jpa.hibernate.ddl-auto=validate|update|create|create-drop|none
```

### Spring Cloud Open Feign

O projeto OpenFeign permite a criação de clientes Rest/SOAP de forma declarativa. O Spring Cloud OpenFeign fornece integração do OpenFeign com Spring Boot por meio de autoconfiguração além de adicionar suporte para anotações Spring MVC. Com ele possível criar clientes Rest através de interfaces que façam uso em conjunto das anotações do OpenFeign e Spring MVC para indicar quais serviços/endpoints serão chamados. Essas anotações são processadas em runtime para criar proxies gerenciados pelo Spring. Para habilitar o Spring Cloud OpenFeign alguns passos devem ser seguidos.

O Spring Cloud OpenFeign limita a flexibilidade do desenvolvimento e pode impactar no desempenho, dessa forma deve ser utilizado para clientes REST simples. Para clientes REST complexos, deve ser considerado utiizar uma biblioteca de clientes REST dedicada.

### Spring Cloud Circuit Breaker

O Spring Cloud Circuit Breaker é a biblioteca padrão do Spring para tratar requisitos de resiliência dos microserviços. Algumas implementações são fornecidas, sendo a resilience4J a implementação padrão a ser utilizada.

O Spring Cloud Circuit Breaker permite a utillização de padrões de implementação que fornecem resiliência aos microserviços.

- Circuit Breaker: Esse padrão permite realizar bloqueios temporários a uma parte do sistema que esteja com falhas.

- Retry: Esse padrão permite repetir execuções que falharem, levando em conta que alguma falhas podem ser transitórias e se resolvem sem intervenção.

- Bulkhead: Esse padrão garante que uma falha em uma parte do sistema não cause o falha no sistema todo. Ele controla o número de chamadas concorrentes que um componente pode ter e isola os recursos, para caso algum apresente falha, os restantes continuem funcionando.

- Rate Limit: Esse padrão limita o volume de requisições a um recurso.

Para habilitar o Spring Cloud Circuit Breaker, é necessário adicionar sua dependência ao pom.xml do projeto.

```
<dependency>
<groupId>
org.springframework.cloud
</groupId>
<artifactId>
spring-cloud-starter-circuitbreaker-resilience4j
</artifactId>
</dependency>
```

Feito isso, o Spring Cloud Circuit Breaker á está autoconfigurado com as opções padrões disponibilizadas pelo módulo.

#### SpringDoc Open API

SpringDocs Open API é uma biblioteca que ajuda a automatizar a geração de documentação de API em projetos Spring.

O SpringDocs utiliza o swagger que além de ser uma implementação da especificação OpenAPI, fornece um conjunto de ferramentas que vão desde o design da API até os testes.

A utilização do SpringDocs pode ser feita de duas formas:

- Code First: A geração da documentação é feita a partir do processamento de anotações inseridas no código desenvolvido. Um dos benefícios dessa abordagem é que a documentação por ser gerada a partir do código, sempre está atualizada sem a necessidade de alteração de documentos externos.

- Design First: Todo o design(contrato) da API é criado antes do início da codificação. Essa abordagem tem como benefício a API ser desenhada como um produto final que será entregue a um cliente, já sendo trabalhando desde o início aspectos como verbos HTTP adequados, requisitos de segurança, performance, usabilidade, além de propiciar uma maior facilidade no aprendizado.

Para habilitar o uso do SpringDocs Open API, sua dependência deve ser incluída no pom.mxml do projeto

```
<dependency>
<groupId>
org.springdoc
</groupId>
<artifactId>
springdoc-openapi-ui
</artifactId>
</dependency>
```

Ao incluir a dependência, o projeto terá novos endpoints configurados:

- /swagger-ui/index.html: Interface do swagger para realizar testes no endpoints.

- /v3/api-docs: Documentação OpenAPI em formato json.

- /v3/api-docs.yaml: Documentação OpenAPI em formato yaml.

### Injeção por atributo, construtor ou setter

O Spring permite que a injeção de dependências seja feita das seguintes formas: - Injeção via construtor: quando a injeção de dependência é feita definição dos construtores das classes. - Injeção via setter: quando a injeção de dependência é feita na definição dos seters das classes. - Injeção via atributo: quando a injeção de dependência é feita definição dos atributo da classe.

É altamente recomendado usar a injeção nos construtores para dependências obrigatórios (o objeto se torna imutável) e a injeção nos métodos setter para dependências opcionais. Os testes unitários são impactados positivamente quando usadas esses abordagens.

### Convenção de nomes

Além de facilitar a legibilidade e a compreensão do código, manter o padrão de nomes dos beans do Spring facilita muito quando trabalhamos com AOP ou criamos alguma feature que faça uso de convenção sobre configuração. É altamente recomendável seguir o padrão dos sufixos: ***Service* * para classes de serviço,** *Repository* *para classes de repositório,* **Controller** ou ***Resource** para os controladores de API.

### Uso de Optional

Optional é uma classe cujo objetivo é encapsular um objeto a fim de informar se o valor desse objeto está presente ou não. É altamente recomendável que todas as classes de repository retornem sempre Optional quando o retorno for um objeto único.

Assim,as classes de serviço devem utilizar os recursos do Optional para tratar possíveis cenários de erro.
