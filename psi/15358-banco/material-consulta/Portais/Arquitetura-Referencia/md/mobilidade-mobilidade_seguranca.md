# Segurança para Aplicativos Móveis [Nova Arquitetura]

A nova arquitetura contempla 3 SDKs para as funcionalidades exclusivas de segurança:

![SDK Segurança](<./imagem/index-imagem-066.png>)

Descrição da imagem - [./imagem/index-imagem-066.md](<./imagem/index-imagem-066.md>)

Os SDKS são integrados e trabalham de forma conjunta atuando em camadas de proteção.

Na representação abaixo é descrito o fluxo de conexão e de lógica de integração.

## Integração e uso dos SDKs

![SDK Segurança](<./imagem/index-imagem-067.png>)

Descrição da imagem - [./imagem/index-imagem-067.md](<./imagem/index-imagem-067.md>)

## 1 - SDK OFD [Topaz OFD]

A ferramenta OFD Topaz é utilizada para viabilizar a gestão dos dispositivos e antifraude dos aplicativos móveis.

O SDK atua em diversas proteções no endpoint do usuário como: - Proteção contra emulador; - Identificação de dispositivos com Jailbreak/Root; - Proteção contra Smishing [Android] - Monitoramento de captura de tela - Coleta de dados de GPS - Alteração nas rotas de navegação [Android] - Identificação de aplicações maliciosas instaladas [Android]

Além das proteçãos locais no endpoint, a solução possui um mecanismo de aferição de risco de transação baseado em score.

A cada transação, os serviços de negócio enviam para a ferramenta de antifraude (SIAAF) os dados da transação em curso. O SIAAF então gerencia o envio de tais dados ao OFD Topaz para consulta do score obtido e com base em modelos previamente configurados aprova ou não a transação em questão.

### Padrão de geração de ID de dispositivo

Para uma gestão efetiva dos dispositivos dos usuários é mandatório a geração de um código identificador único para cada dispositivo, com regra de geração padronizada para toda a empresa.

Há algumas especificações de geração de identificadores disponíveis no mercado e a grande maioria utiliza algoritmos baseados em componentes físicos do dispositivo, IMEI entre outros dados.

Para os aplicativos da CAIXA, nesta nova versão da arquitetura de referencia, o padrão a ser utilizado na identificação única de dispositivos passou a ser implementado pela TOPAZ, em substituição ao UUID do Mobile First.

## 2 - SDK SISET

O SISET é a solução responsável pela gestão de identidades e acesso nos aplicativos móveis da CAIXA.

Os aplicativos móveis deverão utilizar o padrão OAUTH2 e tokens de acesso JWT nos fluxos de login para autenticação dos usuários. Estes tokens estão identificados no modelo de arquitetura como **token usuário** .

## 3 - SDK App Check

A solução Firebase App Check é utilizada para controle da autenticidade dos aplicativos móveis e deverá ser implementada pelos aplicativos móveis para obter tokens que representam a autenticação do aplicativo no serviço do Firebase. Estes tokens estão referenciados no modelo como **token aplicativo** .

Ambos os tokens (usuário e aplicativo), são trafegados como parâmetros no header das requisições HTTP para o *APIM* , onde serão aplicadas as *policies* definidas pelo SIGAM para validação e liberação do acesso aos *serviços de negócio* publicados no *APIM* .

A documentação dessa solução pode ser acessada em [App Check](https://firebase.google.com/docs/app-check)

## Melhores Práticas

### *Pinagem de Certificado*

A comunicação entre o dispositivo e o middleware de mobilidade deverá ser feita obrigatoriamente por meio do protocolo HTTPS, e os aplicativos móveis deverão implementar certificate pinning do middleware para minimizar o risco de interceptação da comunicação por ataques MitM - *man-in-the-middle* .

### *Ofuscação de Código*

Para auxiliar no processo de proteção contra engenharia reversa dos aplicaitivos, orienta-se o uso de solução de ofuscação de código.

Atualmente os aplicativos Caixa utilizam a solução Proguard para tal finalidade.

Essa solução é OpenSource e pode ser utilizada de forma gratuita.

## Outras soluções

### Azion

A solução Azion é empregada para proteger e monitorar a camada Edge, implementando proteções DDoS, Web Application Firewall e Anti Bots.

Descrito na Arquitetura de Referência de [Redes e Comunicação](seguranca-redes_comunicacao.md) .

## Criticidade de Segurança dos Aplicativos

Os Aplicativos deverão passar, anteriormente ao início do desenvolvimento, por uma consultoria das áreas de segurança (GECMI e GEIPF) para verificação dos níveis de segurança exigidos para cada produto/funcionalidade.

De acordo com critérios de risco definidos por estas áreas, os aplicativos/funcionalidades serão enquadrados em uma classificação também definida pelas mesmas áreas.

As definições se diferem para o público de clientes CAIXA (externo) e para os empregados (interno).
