    Backup Multiplataforma

    Assunto: Hardware Multiplataforma

    Solução: Backup Multiplataforma

    Software (s): IBM Spectrum Protect (TSM - Tivoli Storage Manager)

    Hardware (s): Servidores HP DL 380, Storages EMC Vmax 40K e ISILON, Fitoteca ORACLE SL8500, Mainframe z15

    Fabricante (s): IBM -- Spectrum Protect (TSM) e Mainframe z15, DELL -- Storages, HPE -- Servidores do Spectrum Protect (TSM), ORACLE -- Fitotecas, Drivers e Cartuchos

    Objetivo: Apresentar as informações referentes a arquitetura de referência do ambiente de backup multiplataforma, com o objetivo de fornecer uma visão geral da infraestrutura de hardware e software que a suporta.

    Formalização SUART

    1. Número do RTC: 19415434

    2. O que será apresentado neste documento é a arquitetura atualusada para atender as demandas de backup das plataformas open (x86) e intermediaria (SPARC).

    Topologia da Arquitetura

    1. Abaixo segue a topologia macro de todo o ambiente de Backup da CAIXA existente nos datacenters CTC e DTC com seus dispositivos e suas interconexões aos demais dispositivos que compõe a solução de backup.

    2. Abaixo segue a topologia macro de um cluster de Spectrum Protect (TSM) com suas interconexões aos demais dispositivos que compõe a solução de backup como Storages e Fitotecas.

    Características da Arquitetura

    1. A arquitetura de backup em uso atualmente no ambiente multiplataforma (Open e Sparc) é composta pelos seguintes componentes:

      1. Servidor HP Proliant DL380 G8

        1. Servidor do tipo rack, com padrão de arquitetura intel X86, composto por discos mecânicos (HDD), possui múltiplos processadores, fontes e fans para garantir proteção, redundância e alta disponibilidade.

        2. Na solução de backup é utilizado para executar o software IBM Spectrum Protect (TSM) e Library Manager, onde são configurados em cluster para garantir alta disponibilidade da solução, temos no total 19 clusters de TSM.

      2. Storage DELL EMC VMAX 40K

        1. É um subsistema de armazenamento em disco do tipo bloco para ambientes Open System, é utilizado como Diskpool para armazenamento temporário dos arquivos de backup até que estes arquivos sejam migrados para a fitoteca.

      3. Storage DELL EMC ISILON

        1. É um subsistema de armazenamento em disco do tipo NAS (Network Attached Storage) que fornece espaço de armazenamento através de conexões de rede IP por meio dos protocolos NFS, SMB, CIFS, HDFS entre outros. é utilizado para armazenamento temporário (cache) dos arquivos de backup até que sejam migrados para a fitoteca.

      4. StorageTek SL8500

        1. É uma fitoteca automatizada de grande capacidade que suporta até 64 drives e 2.880 cartuchos, dividida em andares ou LSMs (Library Storage Modules), onde são alocados os drives de fita (T10K-C e T10K-D) e os cartuchos magnéticos (T10K-T1 e T2).

        2. Os dados protegidos são armazenados em duas fitotecas ORACLE modelo Storagetek SL-8500 sendo uma instalada no DTC com 64 drives e 1.350 cartuchos e a outra no CTC com 32 drives e 410 cartuchos.

      5. Drive T10000 (T10K)

        1. São os dispositivos que realizam a gravação dos dados de backup nos cartuchos T10K, estes drives ficam internos a fitoteca. Possuímos os modelos T10K-C e T10K-D.

      6. Cartucho T10000 (T10K)

        1. São cartuchos de fita magnética onde os dados dos backups são armazenados. Temos os modelos T10K T1 e T2, onde o T1 possui capacidade de armazenar até 1 TB (um terabyte) de dados, e o T2 possui capacidade de armazenar até 8 TB (oito terabyte) de dados.

      7. IBM Mainframe z15

        1. Mainframe IBM z14 no qual existe uma partição exclusiva para executar o software ELS (Enterprise Library Station) que controla o acesso dos servidores do Spectrum Protect as fitotecas SL 8500.

      8. ELS (Enterprise Library Station)

        1. É um software do fabricante ORACLE instalado e executado em uma partição exclusiva no Mainframe, que permite a comunicação entre os cluster de TSM e as fitotecas SL8500, e coordena a montagem das fitas físicas nos drives T10K (unidades de leitura e gravação).

      9. **TSM Library Manager **

        1. É um serviço executado em um servidor x86 com a função única e exclusiva de controlar o acesso físico a fitoteca SL8500, ele recebe os comandos dos servidores Library Clients e converte para comandos que são enviados para o Library Station (mainframe) que por sua vez comandam a fitoteca para montar ou desmontar um cartucho de fita no drive.

      10. TSM Library Client

        1. É um serviço executado no cluster de backup do TSM, quando o TSM server necessita gravar ou ler uma fita, ele envia os comandos para o Library Manager, que por sua vez converte os comandos e envia para o Library Station (mainframe) que, por sua vez, executa os comandos diretamente na fitoteca.

      11. Spectrum Protect Server (TSM Server)

        1. É um cluster de servidores executando em Windows Server 2012 R2, responsável por receber as conexões dos clientes de backup e armazenar os dados, possuindo conexão a diversas LUNs (unidades logicas) de storages bloco open EMC VMAX e volumes NFS em storages EMC ISILON, que são usadas como área temporária de armazenamento dos backups, estas áreas são chamadas de DiskPools, após a finalização dos backups os arquivos de backup são movidos para as fitas magnéticas utilizando os componentes descritos acima, onde serão guardados pelo período de retenção configurado na política aplicada a cada backup.

      12. Clientes de Backup

        1. São servidores físicos ou virtuais executando os sistemas operacionais Windows, Linux, Unix e Vmware, bancos de dados ORACLE, DB2, PostGrees e MS SQL, servidores de e-mail do Exchange entre outros e que se conectam aos Clusters TSM para enviar arquivos para serem feitos backups e armazenados nos storages que posteriormente são transferidos para as fitotecas para serem arquivados pelo período determinado na política de backup aplicada a cada cliente de backup.

      13. Consoles de Administração

        1. São as consoles de gerenciamento dos Clusters TSM onde são criadas e gerenciadas as políticas de backup e as configurações dos clientes de backup.

    Principais Recomendações de Uso

    1. A solução de backup deve ser utilizada para atender todas as demandas de backup existentes na CAIXA para as plataformas Open (x86) e distribuída (SPARC).

    2. Backup de todas as bases de dados em uso na CAIXA como Oracle, Microsoft SQL Server, DB2, Portgress e Caché.

    3. Backup dos diretórios de aplicações em servidores Web Server.

    4. Backup das bases e Logs de todos os servidores de Active Director.

    5. Backup das DAGs dos servidores de e-mail Microsoft Exchange.

    6. Backup de máquinas virtuais do ambiente Vmware.

    Demais considerações

    Glossário

    1. Controladora – É a unidade autônoma contendo processamento, memoria, cache, portas de acesso a front-end e back-end e é responsável pelo gerenciamento, controle, acesso a discos, proteção, compressão e desduplicação entre outras tarefes importantes executadas em um subsistema de discos.

    2. CIFS (Common Internet File System) – É um protocolo de rede da camada de aplicação usado principalmente para fornecer acesso compartilhado a arquivos, impressoras e portas seriais e comunicações diversas entre nós sobre uma rede.

    3. DAE (Disk Array Enclousure) – É um modulo exclusivo para acomodação de discos ou SSDs e as controladoras são conectadas a ela por meio das portas de back-end que podem ser com tecnologia SAS, Infiniband ou Ethernet com RDMA.

    4. HDD (Hard Disk Drive) – É uma unidade de disco rígido mais comumente chamado de HD que usa pratos magnéticos giratórios e um cabeçote móvel de leitura/gravação para acessar dados.

    5. HDFS (Hadoop Distributed File System) – É um sistema de arquivos distribuído que armazena dados em máquinas dentro do cluster, sob demanda, permitindo uma largura de banda muito grande em todo o cluster.

    6. Infiniband - É uma arquitetura de rede multifuncional de alto desempenho baseada em switch, geralmente chamado de "fabric". O InfiniBand (abreviado como "IB") foi projetado para uso em redes de armazenamento (SAN) ou em redes de cluster. Tornou-se um padrão líder em computação de alto desempenho. 

    7. Cache – É uma porção de armazenamento em tecnologia ultrarrápida e de baixa latência geralmente em memória do tipo DRAM (Dynamic Random Access Memory) ou a mais nova tecnologia SCM (Storage Class Memory) e ela serve para acelerar a leitura e escrita dos dados pelos clientes do storage, por ser mais rápida do que fazer o acesso direto ao disco ou SSD.

    8. DWDM (Dense Wavelength Division Multiplexing ou Multiplexação Densa por Divisão de Comprimento de Onda) – é uma tecnologia que, basicamente, usa diversos lasers para transmitir múltiplos comprimentos de onda de luz simultaneamente, multiplexando os sinais em uma única fibra óptica, e na CAIXA a utilizamos para criar uma rede de baixa latência que interliga os dois datacenters (DTC e CTC).

    9. LAN (Local Area Network) – É uma rede de alta velocidade (10 Gbps) e baixa latência (da ordem de milissegundos) que utiliza o protocolo Ethernet e é utilizada para fazer a comunicação entre os clientes de backup e os Clusters de TSM e também para a comunicação entre os Clusters de TSM e os Storages ISILON.

    10. AS (Network Attached Storage) – É um subsistema de armazenamento em disco conectado a uma rede TCP-IP que possibilita o armazenamento e a recuperação de dados de um local centralizado para usuários autorizados da rede e clientes de sistemas operacionais heterogêneos.

    11. NFS (Network File System) - É um sistema de arquivos distribuídos desenvolvido pela Sun Microsystems, a fim de compartilhar arquivos e diretórios entre computadores conectados em uma rede TCP-IP.

    12. Node – É a unidade autônoma contendo processamento, memoria, cache, portas de acesso a front-end e back-end e é responsável pelo gerenciamento, controle, acesso a discos, proteção, compressão e desduplicação entre outras tarefes importantes executadas em um subsistema de discos.

    13. Back-End – São as portas utilizadas pelos Nodes ou controladoras em uma rede interna privada responsável pelo acesso aos dados, controles e proteção dos discos, utilizando protocolos como Ethernet, Infiniband ou SAS.

    14. Front-End – São as portas Ethernet 10 Gbps utilizadas para conectar os storages aos switches da rede LAN, e são as portas por onde trafegam os dados entre os storages e os servidores.

    15. Processadores – São responsáveis por executar todas as instruções de acesso a discos, controles, proteções, compressão e desduplicação entre outras tarefas executadas pelas controladoras.

    16. SAN (Storage Area Network) – É uma rede de alta velocidade (16 Gbps) e baixíssima latência (da ordem de microssegundos), que utiliza como meio físico a fibra optica e o protocolo Fiber Channel e é utilizada para fazer a comunicação entre os Clusters de TSM e os Storages VMAX e as Fitotecas SL8500.

    17. SAS (Serial Attached SCSI) - É a evolução tecnológica do protocolo SCSI com mais performance e flexibilidade, é uma tecnologia de transmissão de baixo custo, full-duplex (transmite e recebe dados ao mesmo tempo) e com taxas de transferência de 3, 6 ou 12Gbps (gigabits por segundo).

    18. SCM (Storage Class Memory) – é um novo tipo de memória que utiliza na sua criação memorias DRAM e memória Flash, é usada para acelerar o acesso de leitura e gravação nos storages mais modernos e de alta performance.

    19. SMB (Server Message Block) – É um protocolo de rede da camada de aplicação usado principalmente para fornecer acesso compartilhado a arquivos, impressoras e portas seriais e comunicações diversas entre nós sobre uma rede.

    20. SSD (Solid State Drive) – É um tipo de dispositivo de armazenamento de dados mais novo e rápido que armazena dados em chips de memória que podem ser acessados instantaneamente.

    21. Storage – É um subsistema de armazenamento em disco podendo utilizar discos mecânicos (HDDs) ou drives de estado sólido (SSDs), vejamos abaixo os principais componentes de um storage.

    22. S3 (Amazon Simple Storage Service) - É um serviço de armazenamento de objetos construído para armazenar e recuperar qualquer volume de dados de qualquer local que oferece escalabilidade, disponibilidade de dados, segurança e performance.
